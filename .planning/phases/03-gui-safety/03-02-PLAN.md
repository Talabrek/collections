# 03-02: Re-fetch Progress Before Mutations and Handle Inventory Full

## Objective

Fix reward claiming to use fresh progress data and allow claiming even when inventory is full (items drop at player feet instead of blocking claim).

## Context

Current issues identified in research:
1. `attemptClaimReward()` uses `getProgress()` which returns cached data - if progress changed since GUI opened, claim may succeed/fail incorrectly
2. Pre-check `hasInventorySpace()` blocks claim when inventory full, but `giveRewards()` already handles overflow by dropping items - these conflict
3. Spec says items should drop at feet, not block claim

The fix addresses GUI-02 (re-fetch before mutation) and GUI-03 (handle inventory full).

## Tasks

<task id="1">
**Re-fetch progress using getProgressBlocking in attemptClaimReward**

File: `src/main/java/com/blockworlds/collections/gui/CollectionDetailGUI.java`

In `attemptClaimReward()` method (line ~434), change:
```java
PlayerProgress progress = playerDataManager.getProgress(player.getUniqueId());
```

To:
```java
// Re-fetch fresh progress data, not cached/stale data
PlayerProgress progress = playerDataManager.getProgressBlocking(player.getUniqueId());
```

This ensures the completion and claimed checks use current state, not the state from when the GUI was opened.
</task>

<task id="2">
**Remove inventory space pre-check**

File: `src/main/java/com/blockworlds/collections/gui/CollectionDetailGUI.java`

In `attemptClaimReward()` method, remove the entire inventory space check block (lines ~461-465):

```java
// REMOVE THIS BLOCK:
if (!rewardManager.hasInventorySpace(player, rewards)) {
    player.sendMessage(configManager.getMessage("inventory-full"));
    guiManager.playErrorSound(player);
    return;
}
```

The `RewardManager.giveItems()` method already handles overflow by:
1. Calling `player.getInventory().addItem(item)`
2. Dropping leftover items via `player.getWorld().dropItemNaturally()`
3. Sending the "inventory-full" message when items are dropped

This allows claims to proceed and properly communicates when items were dropped (only when they actually drop, not preemptively).
</task>
