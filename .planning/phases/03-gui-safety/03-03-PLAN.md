# 03-03: Add State Versioning and Double-Claim Prevention

## Objective

Prevent double-claim exploits via rapid clicking and detect when progress changed since GUI was opened.

## Context

Current vulnerabilities identified in research:
1. **Double-click race:** Fast double-clicks can trigger multiple `attemptClaimReward()` calls before first claim persists - both pass `hasClaimedReward()` check
2. **Stale state:** GUI shows "claimable" based on open-time data - if admin resets progress while GUI open, player can claim for incomplete collection

This plan depends on 03-02 (which adds `getProgressBlocking()`) and adds double-claim prevention and state change detection.

## Tasks

<task id="1">
**Add AtomicBoolean claiming lock**

File: `src/main/java/com/blockworlds/collections/gui/CollectionDetailGUI.java`

Add import at top:
```java
import java.util.concurrent.atomic.AtomicBoolean;
```

Add field after line 40 (after the `private final Inventory inventory;` field):
```java
// Prevents double-claim race from rapid clicks
private final AtomicBoolean claiming = new AtomicBoolean(false);
```

Modify `attemptClaimReward()` to check and set the lock:

At the START of the method, add:
```java
// Prevent double-click race - only one claim attempt at a time
if (!claiming.compareAndSet(false, true)) {
    return;  // Another claim already in progress
}
```

Wrap the rest of the method in try-finally to release lock:
```java
try {
    // ... existing claim logic (progress fetch, validation, giveRewards, claimReward) ...
} finally {
    claiming.set(false);
}
```
</task>

<task id="2">
**Add state versioning to detect progress changes**

File: `src/main/java/com/blockworlds/collections/gui/CollectionDetailGUI.java`

Add fields after the `claiming` field:
```java
// State snapshot from when GUI was opened - for staleness detection
private final boolean wasCompleteOnOpen;
private final boolean wasClaimedOnOpen;
```

In the constructor, after line 69 (after inventory creation), add state capture:
```java
// Capture completion state at open time for staleness detection
PlayerProgress openProgress = playerDataManager.getProgress(player.getUniqueId());
this.wasCompleteOnOpen = openProgress != null && openProgress.hasCompleted(collection.id());
this.wasClaimedOnOpen = openProgress != null && openProgress.hasClaimedReward(collection.id());
```

Note: Using `getProgress()` here is fine - this is just for comparison, not mutation. The open() method already gates on `getProgressBlocking()`.

In `attemptClaimReward()`, AFTER the `getProgressBlocking()` call and null check, but BEFORE the completion/claimed checks, add state change detection:
```java
// Detect if state changed since GUI was opened
boolean nowComplete = progress.hasCompleted(collection.id());
boolean nowClaimed = progress.hasClaimedReward(collection.id());

if (nowComplete != wasCompleteOnOpen || nowClaimed != wasClaimedOnOpen) {
    player.sendMessage(configManager.getMessage("progress-changed"));
    guiManager.playErrorSound(player);
    populateInventory();  // Refresh GUI to show current state
    return;
}
```

This ensures that if an admin reset progress or another system modified state, the claim is rejected with a clear message and the GUI is refreshed.
</task>
