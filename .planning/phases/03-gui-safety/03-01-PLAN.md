# 03-01: Cancel All Click Types in GUI Handlers

## Objective

Fix click handling in GUIListener to cancel ALL click types when a custom GUI is open, preventing shift-click, number key, double-click, and drag exploits.

## Context

Current implementation cancels clicks but has subtle issues:
1. `event.getInventory().equals(holder.getInventory())` always returns true (getInventory returns top inventory) but doesn't distinguish player inventory clicks
2. Clicks in player inventory section pass through to `handleClick()` which then checks rawSlot
3. Drag events only check if top inventory matches, not if any drag slots are in GUI

The research identified that while most exploits are blocked by `setCancelled(true)`, the implementation should be more explicit about what gets routed to handlers vs simply cancelled.

## Tasks

<task id="1">
**Improve InventoryClickEvent handling in GUIListener**

File: `src/main/java/com/blockworlds/collections/listener/GUIListener.java`

Modify `onInventoryClick()` to:
1. Cancel event FIRST, before any inventory check (line ~48 should move up)
2. Calculate top inventory size via `holder.getInventory().getSize()`
3. Get raw slot via `event.getRawSlot()`
4. Only call `holder.handleClick(event)` if `rawSlot >= 0 && rawSlot < topSize`
5. For clicks outside GUI bounds (rawSlot < 0 or rawSlot >= topSize), simply return after cancel

Current code:
```java
// Only handle clicks in our GUI inventory
if (!event.getInventory().equals(holder.getInventory())) {
    return;
}
// Cancel the event to prevent item movement
event.setCancelled(true);
// Route to the GUI handler
holder.handleClick(event);
```

Change to:
```java
// Cancel ALL clicks when our GUI is open - prevents item movement
event.setCancelled(true);

// Only route clicks actually in GUI slots to handler, not player inventory
int topSize = holder.getInventory().getSize();
int rawSlot = event.getRawSlot();

// Click outside inventory bounds or in player inventory section
if (rawSlot < 0 || rawSlot >= topSize) {
    return;
}

// Route to the GUI handler
holder.handleClick(event);
```
</task>

<task id="2">
**Improve InventoryDragEvent handling in GUIListener**

File: `src/main/java/com/blockworlds/collections/listener/GUIListener.java`

Modify `onInventoryDrag()` to check if ANY of the affected slots are in the GUI inventory, not just top-level inventory match.

Current code:
```java
if (event.getInventory().equals(holder.getInventory())) {
    event.setCancelled(true);
}
```

Change to:
```java
// Cancel if ANY drag slot is in GUI inventory
int topSize = holder.getInventory().getSize();
for (int slot : event.getRawSlots()) {
    if (slot >= 0 && slot < topSize) {
        event.setCancelled(true);
        return;
    }
}
```

This ensures dragging that starts in player inventory but extends into GUI is also blocked.
</task>
