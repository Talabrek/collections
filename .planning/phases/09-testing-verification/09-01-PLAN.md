Replace the `javaPlugin.getFile()` call on line 90 with a reflection-free approach using `getClass().getProtectionDomain().getCodeSource().getLocation()`.

The fix:
```java
// Replace:
try (JarFile jar = new JarFile(javaPlugin.getFile())) {

// With:
File jarFile;
try {
    jarFile = new File(plugin.getClass().getProtectionDomain().getCodeSource().getLocation().toURI());
} catch (URISyntaxException e) {
    plugin.getLogger().log(Level.WARNING, "Failed to locate plugin JAR file", e);
    return;
}
try (JarFile jar = new JarFile(jarFile)) {
```

Add import: `import java.net.URISyntaxException;`

Remove the instanceof check for JavaPlugin since this approach works for any Plugin.

This is the standard approach for accessing the plugin's own JAR file without requiring protected access.
