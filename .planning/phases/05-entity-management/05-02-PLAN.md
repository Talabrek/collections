Review validateActiveCollectibles() to ensure it catches orphaned tracking entries:

1. **Current state:** Checks despawn timeout and location validity, but does NOT check if entity actually exists.

2. **Add entity existence check:** Research recommends periodic validation as safety net for edge cases events miss:
   ```java
   // Add to validateActiveCollectibles() after existing checks:

   // Check if entity still exists (safety net for missed EntityRemoveEvent)
   if (collectible.spawned() && collectible.hitboxId() != null) {
       Entity entity = Bukkit.getEntity(collectible.hitboxId());
       if (entity == null || entity.isDead()) {
           // Entity gone but we thought it was spawned - orphaned entry
           toDespawn.add(collectible.id());
           if (debug) {
               plugin.getLogger().info("Removing orphaned collectible " +
                   collectible.id() + " - entity no longer exists");
           }
           continue;
       }
   }
   ```

3. **Place this check early in the loop:** Before timeout and location checks, since if entity is gone, other checks are moot.

4. **Note about Bukkit.getEntity():** Research warns against using this in hot paths, but validity task runs infrequently (configured interval, default minutes not seconds), so this is acceptable.

5. **Verify entityToCollectible cleanup:** When despawning orphaned collectible, the despawnCollectible() method (from Plan 05-01) should remove from both indexes.
