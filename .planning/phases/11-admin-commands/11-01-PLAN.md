Add three new methods to PlayerDataManager for offline player operations:

1. `loadPlayerByUuid(UUID playerId)` - Public method that loads player data from storage without requiring a Player object. Returns CompletableFuture<PlayerProgress>. If player is already cached, returns cached version. Otherwise loads from storage but does NOT cache (to avoid memory leaks for offline players).

2. `addItemOffline(UUID playerId, String collectionId, String itemId)` - Async method for adding item to offline player. Uses load-then-modify-then-save pattern:
   - If player is cached (online), delegate to existing addItem()
   - Otherwise: storage.loadPlayer(playerId) -> modify progress -> storage.savePlayer(progress)
   - Returns CompletableFuture<Boolean> (true if item was newly added)

3. `completeCollectionOffline(UUID playerId, String collectionId, List<String> itemIds)` - Async method for force-completing a collection for offline player. Adds all items and marks collection complete.
   - If player is cached (online), modify cache directly then persist
   - Otherwise: storage.loadPlayer -> add all items -> markComplete -> storage.savePlayer
   - Returns CompletableFuture<Void>

4. `getProgressOffline(UUID playerId)` - Async method to get progress snapshot for offline player inspection.
   - If player is cached (online), return cached immediately
   - Otherwise: load from storage (does not persist to cache)
   - Returns CompletableFuture<PlayerProgress>

Implementation notes:
- Use existing storage.loadPlayer() and storage.savePlayer() methods
- Use orTimeout(30, TimeUnit.SECONDS) on all async operations
- Log errors via plugin.getLogger().log(Level.WARNING, ...)
- Do NOT cache offline player data to avoid memory leaks - load, modify, save, discard
- For online players, always use the cache to ensure consistency

```java
/**
 * Log an admin action for audit trail.
 * Format: [ADMIN] {action} executed by {executor} on player {target}: {details}
 *
 * @param action    The action type (INSPECT, FORCE_COMPLETE, RESET, etc.)
 * @param executor  The command executor name (player name or "CONSOLE")
 * @param targetId  The target player's UUID
 * @param targetName The target player's name (may be null for never-joined)
 * @param details   Additional details about the action
 */
public void logAdminAction(String action, String executor, UUID targetId, String targetName, String details) {
    String target = targetName != null ? targetName : targetId.toString();
    plugin.getLogger().info(String.format(
        "[ADMIN] %s executed by %s on player %s: %s",
        action, executor, target, details
    ));
}
```

This method will be called by CollectionsCommand when admin commands execute. The plugin logger automatically adds timestamps.
