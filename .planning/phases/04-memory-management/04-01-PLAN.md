# 04-01: Fix collectLocks Map Cleanup

## Objective

Fix the memory leak where `collectLocks` map entries are not removed when players quit, causing unbounded growth over time.

## Context

The `CollectibleInteractListener` maintains two per-player maps:
- `lastCollectTime` - cooldown timestamps (already cleaned on quit)
- `collectLocks` - AtomicBoolean locks for race condition handling (NOT cleaned on quit)

The `cleanupPlayer()` method only removes `lastCollectTime` entries, leaving `collectLocks` entries orphaned. While each entry is small (~32 bytes), this creates unbounded memory growth over extended operation.

Research reference: `.planning/phases/04-memory-management/04-RESEARCH.md`
