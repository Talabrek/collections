<task type="auto">
  <name>Task 1: Migrate PlayerListener to EntityScheduler</name>
  <files>src/main/java/com/blockworlds/collections/listener/PlayerListener.java</files>
  <action>
Replace both BukkitScheduler usages with EntityScheduler:

**Line 50-54 (recipe unlock):**
Before:
```java
Bukkit.getScheduler().runTask(plugin, () -> {
    if (player.isOnline()) {
        recipeManager.unlockRecipesForPlayer(player);
    }
});
```
After:
```java
player.getScheduler().run(plugin, task -> {
    recipeManager.unlockRecipesForPlayer(player);
}, null);  // null = retired callback (player logged out)
```

**Line 60-67 (visibility refresh):**
Before:
```java
Bukkit.getScheduler().runTaskLater(plugin, () -> {
    if (player.isOnline()) {
        GoggleManager goggleManager = plugin.getGoggleManager();
        if (goggleManager != null) {
            goggleManager.refreshVisibilityForPlayer(player);
        }
    }
}, 20L);
```
After:
```java
player.getScheduler().runDelayed(plugin, task -> {
    GoggleManager goggleManager = plugin.getGoggleManager();
    if (goggleManager != null) {
        goggleManager.refreshVisibilityForPlayer(player);
    }
}, null, 20L);  // retired callback, delay in ticks
```

**Key points:**
- EntityScheduler handles player.isOnline() check internally via retired callback
- First `null` is the retired callback (called if player logs out before execution)
- For runDelayed, delay is the last parameter
  </action>
  <verify>Compile: `./gradlew compileJava` passes</verify>
  <done>Both scheduler calls in PlayerListener use player.getScheduler()</done>
</task>

```java

```
After:

}, null, 10L);

**Why EntityScheduler for firework:**
- Firework is an entity with its own position/region
- If server uses Folia regions, firework may be in different region than when spawned
- EntityScheduler ensures task runs on correct region thread

  <name>Task 3: Migrate ArmorChangeListener to EntityScheduler</name>
  <files>src/main/java/com/blockworlds/collections/listener/ArmorChangeListener.java</files>
  <action>
Replace RegionScheduler usage with EntityScheduler:

**Line 40-48:**
Before:
```java
Bukkit.getRegionScheduler().run(plugin, player.getLocation(), task -> {
    if (player.isOnline()) {
        goggleManager.refreshVisibilityForPlayer(player);
        ...
    }
});
```
After:
```java
player.getScheduler().run(plugin, task -> {
    goggleManager.refreshVisibilityForPlayer(player);

    if (plugin.getConfigManager().isDebugMode()) {
        plugin.getLogger().info("Refreshed collectible visibility for " + player.getName() +
                " after helmet change");
    }
}, null);
```

**Why EntityScheduler over RegionScheduler:**
- RegionScheduler schedules based on location at call time
- Player may move between event and task execution
- EntityScheduler follows the entity, ensuring task runs on correct thread
- No need for isOnline() check - handled by retired callback
  </action>

  <done>ArmorChangeListener uses player.getScheduler().run()</done>
